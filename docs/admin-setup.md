# 관리자 기능 설정

Firebase Spark + Workers 무료 구조를 유지합니다. 서비스 계정 키를 생성하지 않습니다.
Workers는 Firebase ID 토큰을 검증하고 `users/{UID}`의 active=true, role=admin을
확인합니다. Firestore REST 쓰기도 같은 사용자 토큰을 보내므로 Rules에서 다시 검증합니다.
관리자 역할을 부여하는 API는 없습니다. 학생은 자신의 역할을 변경할 수 없습니다.

## 최초 관리자 지정 (사용자 승인 후)

1. Firebase Authentication에서 별도 관리자 이메일/비밀번호 계정을 직접 만듭니다.
   비밀번호를 채팅이나 Git에 남기지 않습니다. 관리자 본인의 UID를 복사합니다.
2. Firestore `users/{관리자 UID}`에 displayName(string), role(string: admin),
   active(boolean: true)를 직접 지정합니다. 기존 테스트 학생은 학생으로 유지합니다.
3. 검증된 `firestore.rules` 내용을 Firebase 콘솔 규칙 탭에 적용하고 게시합니다.
   기존 사용자 데이터는 수정하거나 지우지 않습니다. 이 단계는 관리자 쓰기 권한을
   활성화하므로 대상 계정과 함께 사용자 승인을 받아 실행합니다.
4. 로컬 사이트에 관리자 계정으로 로그인하면 9000 관리자 메뉴가 표시됩니다.
   회사 테스트 문서를 만들고 공지/이벤트를 게시해 학생 계정에서 조회합니다.
   사이트/Workers 외부 배포는 별도입니다.

## 제공하는 기능과 제한

- 기업: 이름·코드·분류·소개·상장 상태 등록/수정. 새 기업에만 기준가격과 발행 수량 설정.
  기존 가격·회사 현금·매출·학생 자산은 수정할 수 없습니다.
- 뉴스/공지: 문서 ID로 등록/수정, 대상 기업 ID 또는 전체 공지. 저장 시 게시 시간이 갱신됩니다.
- 이벤트: 대상 기업 ID·내용·시작/종료 시간 등록/수정. 학생 시장 뉴스 화면에 게시됩니다.
  기간은 안내 정보이며 자동 발동·주가/현금 효과는 없습니다.
- 참가자: Authentication에 이미 만든 UID의 참가 이름·학생/동아리장·활성 상태·담당 기업 설정.
  참가 정보와 담당 기업은 Firestore commit 한 번으로 원자적으로 저장합니다.
  Auth 계정 생성, 비밀번호 변경, 초기 자산 지급은 이 페이지에 포함하지 않습니다.
- 삭제 기능은 없습니다. 잘못된 기업은 중지, 참가자는 비활성화할 수 있습니다.
- 목록 상한은 기업/참가자/이벤트 100개, 공지 30개입니다. 현재 페이지네이션은 없으므로
  참가자가 100명 이상이면 확장 후 사용하세요.

관리자는 Firestore 규칙이 허용하는 콘텐츠를 SDK로 직접 작성할 수도 있습니다.
Workers만을 유일한 쓰기 경로로 강제하는 설계는 아닙니다. 모든 역할/자산 제한은
Rules에서도 적용하며, 관리자 권한 부여/변경과 포트폴리오 쓰기는 콘솔에서만 가능합니다.
향후 감사 로그·행사 규모에 맞는 페이지네이션·초기자산 지급·이벤트 효과가 별도 작업입니다.

## 검증

`node --test --test-isolation=none tests/*.test.mjs`

Firestore Standard 로컬 에뮬레이터에서 `tests/rules/firestore.test.mjs`도 실행했습니다.
학생/비활성 관리자 접근 차단, 역할 상승 차단, 기존 관리자 보호, 경제 필드 수정 차단,
콘텐츠 쓰기 허용을 검증합니다. 실서비스 설정과 관리자 로그인의 최종 확인은 계정 지정 후 진행합니다.

## 회원가입 방식으로 변경

현재는 사이트 로그인 창에서 학생이 이름·이메일·비밀번호로 직접 가입합니다.
`/api/register`는 검증된 토큰의 UID만 사용하며 학생 프로필과 초기 가상 자산을
원자적으로 생성합니다. 생성 전용 조건과 Rules로 중복 지급 및 권한 상승을 차단합니다.
기존 계정의 비활성 상태를 가입 재시도로 해제하지 않습니다.
관리자는 참가자를 새로 만들지 않고 목록에서 학생을 선택해 사장 역할·활성 상태·담당 기업을 변경합니다.
문서 ID는 기업·공지·이벤트에서 자동 생성하며, 기업 선택도 이름 목록으로 제공합니다.

이 변경을 운영 DB에서 사용하려면 갱신된 firestore.rules를 게시해야 합니다.
이전 규칙에서는 학생의 프로필/초기 자산 생성이 차단됩니다. 이때 Firebase Auth 계정이
먼저 생성됐더라도 같은 이메일·비밀번호로 회원가입을 다시 시도하면 참가 등록을 완료할 수 있습니다.
Authentication 이메일/비밀번호 가입 기능은 활성화되어 있어야 합니다.
검증: API 36개, Standard 에뮬레이터 Rules 9개 통과.

## 학교 이메일 인증

가입 화면은 @hcu.hs.kr만 허용하고 Firebase의 한국어 인증 메일을 전송합니다.
학생은 메일 링크를 누른 뒤 '인증 완료 확인'을 눌러야 참가자/초기 자산 등록이 완료됩니다.
이때 Firebase 계정 reload와 ID 토큰 강제 갱신을 수행합니다. 학교 메일 인증은
Worker의 서명 검증된 email/email_verified 클레임과 Firestore Rules에서 모두 확인합니다.
활성 관리자 역할이 이미 지정된 계정은 예외이며, 학교 외부 이메일로 새 관리자를
만들거나 스스로 역할을 바꾸는 가입 경로는 없습니다.

Firebase Spark에서 이 구성은 앱의 참가 등록·데이터 접근을 차단하는 방식입니다.
공개 Firebase Auth API 자체의 계정 생성까지 학교 도메인으로 강제 차단하는
서버 훅은 설치하지 않습니다. 외부 이메일 Auth 계정이 만들어져도 참가 등록과
기업·자산 접근은 차단됩니다. Cloud Functions/Blaze나 추가 메일 서비스는 사용하지 않습니다.

인증 메일의 실제 발송/학교 수신함 도착은 학교 계정으로 시험해야 합니다.
스팸메일함 안내는 가입 전과 인증 대기 화면 모두 강조됩니다.
재발송 버튼은 누른 뒤 60초 동안 비활성화되며 Firebase 발송 제한도 적용됩니다.
메일 템플릿은 Firebase Authentication → Templates → 이메일 주소 확인에서 확인합니다.
참고: https://firebase.google.com/docs/auth/web/manage-users#send_a_user_a_verification_email

적용 순서: 최신 firestore.rules를 콘솔에서 게시한 다음 사이트를 새로고침합니다.
학교 계정으로 가입 → 스팸메일함까지 확인 → 링크 클릭 → 인증 완료 확인 → 자산 조회를 점검합니다.
기존 관리자 로그인이 계속 되는지도 확인합니다.
검증: API 37개, Standard Rules 에뮬레이터 10개 통과(실제 메일 발송은 미실행).

# 산업스파이 2명 정책과 일일 발각

- 고용비: 회사당 최대 2명, 100만 원. 대상 회사 정산 일매출의 2.5%를 가져온다. 기간 제한은 없지만 발각되면 활동이 끝난다.
- 기존 복수 인원은 가장 먼저 고용한 활동 인원 2명까지 남기고 나머지는 `remaining: 0`으로 종료한다. 사용자가 선택한 대로 환불하지 않는다. 고용 영수증과 기존 에이전트 자료는 삭제하지 않으며 별도 정책 전환 영수증을 남긴다.
- 신규 고용은 클라이언트와 Firestore 규칙 모두 2명으로 제한한다. 기존 종료 인원은 복구하지 않는다. 발각 후에는 새 고용비를 지불해야 한다.

## 매일 정산 순서

기존 GitHub Actions의 오전 7시 55분(한국 시간) 작업에서 마감된 선택 이벤트를 적용한 다음, 일반 영업수익·배당 정산 **전에** 전체 회사의 활동 가능한 산업스파이 중 무작위 1명을 뽑는다. 스파이마다 같은 확률이며, 당일 활동 시작 전인 인원은 제외한다. 대상이 없으면 그날의 추첨은 빈 결과로 확정하고 뉴스도 올리지 않는다. 정산 후 기존 스파이 이체는 별도 마지막 단계에서 진행한다.

발각된 인원은 즉시 활동 종료한다. 고용 회사 계좌에서 대상 회사 계좌로 `floor(대상 일매출 × 2.5%) × 150%`의 보상금을 지급하며, 반 원은 원 단위 올림한다. 예를 들어 일매출 400만 원이면 예정 탈취액은 10만 원, 보상금은 15만 원이다. 예상 매출에는 해당 정산에 성숙한 투자와 적용 이벤트를 반영한다. 기존 탈취의 자금/피해 상한과 별개로 시도한 2.5% 금액을 기준으로 보상하며, 고용 회사 잔액이 음수가 되어도 보상한다. 보상금 자체는 영업 매출이나 주주 배당으로 계산하지 않는다.

발각 인원, 회사 간 보상금, 명부 버전, 처리 영수증, 자동 뉴스는 하나의 IAM 서버 트랜잭션에서 기록한다. 뉴스에는 두 기업명, 기준 매출, 예정 탈취액, 실제 보상금, 활동 종료를 표시한다. 기사 분류는 기업 뉴스다. 기사 ID가 기존 기사와 충돌하면 덮어쓰지 않고 발각 처리를 모두 취소한다.

`spyRounds/preflight-d<한국날짜번호>`로 하루 한 번만 확정한다. 15분 재시도·동시 실행 시 추가 추첨/중복 보상/중복 뉴스가 없다. 실패하면 일반 정산을 시작하지 않는다. 이전 날짜 정산이 중단되어 있으면 먼저 복구한다. 배포나 수동 복구 전에 이미 당일 정산이 시작됐다면 그날은 소급 발각하지 않고 다음 날부터 정상 추첨한다. 관리자 화면의 수동 정산도 이 사전 처리 기록이 있어야 실행한다.

## 배포

기존 전용 서비스 계정과 Workload Identity 연결을 그대로 사용하며 새 비밀키·유료 서비스·접근 권한을 추가하지 않는다. GitHub 정기 실행은 지연될 수 있어 실제 실행 시각이 매일 07:55 정각이라고 보장하지 않는다. 코드상 순서는 발각 → 보상/뉴스 → 영업수익/배당 → 남은 스파이 이체로 고정한다.

1. 새 Firestore 규칙을 게시한다(고용 인원/비율 검증만 변경).
2. 병합 후 `Daily settlement and rankings`의 `spies-policy-only` 모드로 기존 명부만 전환한다. 이 모드는 추첨·보상·영업 정산·뉴스·순위 갱신을 실행하지 않는다.
3. 사이트를 배포한다. 다음 정산부터 일일 추첨이 자동 적용된다.

정책 전환은 `spyAutomation/two-agent-v2`로 재실행을 방지한다. 실제 사용자 데이터를 테스트 목적으로 생성/초기화하지 않는다. 테스트는 루프백 `demo-*` 에뮬레이터에서 수행한다.

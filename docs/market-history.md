# 종목 전체 체결 차트

`sparkBooks/{test-a|test-b}/trades/{fillId}`에 종목 코드, 체결가격, 수량, 주문장 버전, 서버 체결 시각만 생성한다. 계정 UID·이름·이메일·개인 주문번호는 저장하지 않는다. 매수/매도 양쪽에 하나씩 복제한 개인 체결과 달리 공개 체결은 거래 한 쌍당 정확히 하나다.

개인 자산/주문/체결과 이 기록은 같은 Firestore 트랜잭션으로 확정한다. 개인 체결 생성 규칙이 공개 기록의 동일 가격/수량/버전/시각을 `getAfter()`로 요구한다. 공개 기록의 생성 규칙도 주문장이 같은 요청에서 한 버전 진전하고 실제 매칭 체결인지 확인한다. 공개 기록만 생성, 누락, 가격 조작, 추가 UID 필드, 기존 기록 변경/삭제를 허용하지 않는다. 주문장 규칙 자체에 추가 조회를 넣지 않아 기존 규칙 조회 한도를 지킨다.

활성 참가자는 종목별 최근 100건까지 조회한다. 비로그인·미인증·비활성 계정은 읽지 못하고 다른 학생의 개인 체결/자산 접근도 계속 차단한다. 차트는 개인 거래 여부와 관계없이 이 공개 기록을 체결 순으로 표시한다. 1분봉·5분봉·한국시간 자정 기준 일봉으로 시가·고가·저가·종가와 수량 합계인 거래량을 계산한다. 빨강은 종가가 시가보다 높은 양봉, 파랑은 음봉, 회색은 시가와 종가가 같은 봉이다. 아래 막대는 실제 체결 수량이며, MA 5는 표시된 봉의 종가 5개가 모인 뒤에만 그린다. 시간 간격에 거래가 없으면 가상의 봉을 채워 넣지 않는다. 최근 100건 조회 범위의 첫 봉은 일부 체결만 포함할 수 있으므로 화면에 이 제한을 표시한다. 확대/축소로 보이는 봉 수를 조절하고 커서 또는 좌우 방향키/Home/End로 OHLC·거래량을 확인한다. 호가·체결 새로고침이나 새 주문 후 차트를 갱신한다.

## 공개 사이트 활성화

1. 사이트 번들을 먼저 배포해 새 체결 기록 형식과 읽기를 준비한다.
2. Firebase 프로젝트 `hcujusik` → Firestore Database → `(default)` → 규칙에서 저장소 루트의 **firestore.rules 전체 내용**으로 바꿔 게시한다. 기존 내용에 `allow read, write: if true` 등을 추가하지 않는다.
3. 열린 사이트의 새 버전 안내를 누르거나 새로고침한다. 이후 확정되는 체결부터 전체 차트에 기록된다. 다른 학생이 거래한 뒤 호가·체결 새로고침으로 같은 종목 가격 흐름이 보이는지 확인한다.

게시 전에는 `종목 차트 연결 준비 중`을 표시하고, 기존 규칙 아래의 매칭은 유지한다. 게시 후 새 규칙은 공개 기록을 빠뜨리는 구버전 매칭을 원자적으로 거부하므로, 오래 열린 브라우저는 새로고침해야 한다. 규칙을 게시하지 않은 상태에서 개인 체결을 전체 차트인 것처럼 대신 표시하지 않는다.

과거 개인 체결 전체를 열람하거나 재구성하지 않는다. 기능 활성화 이전 거래는 차트에 소급 반영되지 않는다. 각 화면 갱신에서 공개 기록 최대 100건을 추가로 읽으며, 쓰기는 체결당 공개 문서 1개 늘어난다. 자동 폴링이나 추가 유료 서비스는 사용하지 않는다.

검증: `pnpm test`, `FIRESTORE_EMULATOR_HOST=127.0.0.1:8082 pnpm test:rules`, `pnpm build`. 로컬 합성 참가자의 실제 에뮬레이터 매칭으로 다른 참가자의 체결 공개, 개인 체결 비공개, 공개 기록 누락/위조 거부, 구규칙→신규칙 전환을 확인한다. 새 규칙은 검증용 초안이며 공개 범위를 넓히기 전에 검토한다.

# 매출 공식 이벤트

매출은 (판매가격 - 생산원가) × 생산력으로 계산한다. 새 이벤트는 설비/직원 수량과 회사 잔액을 수정하지 않고 정산 시 공식 입력에만 적용한다.

| 효과 | 입력 | 예시 |
| --- | --- | --- |
| 판매가격 변동 | -100~500% | +10% |
| 판매가격 증감 | ±1,000,000원, 0 제외 | +100원 |
| 생산원가 변동 | -100~500% | +20% |
| 생산원가 증감 | ±1,000,000원, 0 제외 | -50원 |
| 생산력 변동 | -100~500% | -30% |
| 생산력 증감 | ±1,000,000개/일, 0 제외 | +200개/일 |

각 항목은 기본 수치 × max(0, 100 + 비율 합계) / 100 + 고정 증감 합계 순서로 반영하고 정수 반올림한다. 판매가격/생산력 최소 0, 원가 최소 1이다. 매출 최소 0, 기존 매출 상한은 유지한다. 비율 효과끼리, 고정 증감끼리 합산하므로 이벤트 순서가 결과를 바꾸지 않는다. 최종 일매출 비율 이벤트는 계산 후 적용한다.

정산 적용 횟수 1~365회. 회사의 settlementCount 기반으로 기존 정산 재시도/중복 방지 절차를 그대로 사용한다. 랜덤/선택형 모두 동일 계산을 쓴다. 선택형은 마감 전 결과를 숨기고 관리자/자동 처리만 실제 효과를 적용한다.

새 발행 목록에서 설비 효율 변동은 제외한다. 기존 효율 이벤트의 해석/이력은 보존한다. 자금/설비/직원/투자비용/배당 상한 효과는 유지한다. 기존 기업 자료와 적용 이벤트를 삭제하거나 재작성하지 않는다.

배포 순서: 수정된 firestore.rules 게시 → PR 병합 및 Pages 배포. 기존 정산 워크플로는 다음 실행부터 새 계산을 사용한다. 운영 데이터에 테스트 이벤트를 발행하지 않는다.

## 여러 효과를 가진 랜덤 이벤트

이벤트 한 건에 1~20개 효과를 추가한다. 각 효과는 개별 회사 목록(복수 선택 또는 전체)을 갖는다. 같은 회사가 여러 효과에 포함될 수 있다. 제목·상황·뉴스는 한 번만 작성한다. 선택형 이벤트 동작은 유지한다.

API는 effects: [{ companyIds: ['company-id'], effect: { kind: 'cash', amount: 1000 } }] 형식이다. effects가 없는 과거 단일 효과 요청은 그대로 지원한다. 대상 미선택은 전체 적용으로 대체하지 않고 거절한다.

저장은 events 문서 한 건과 effect별 eventOutcomes/options 문서로 구성한다. 회사별·효과별 receipt는 eventId_e{index}이며 부모 eventId와 효과 번호를 검증한다. 한 효과의 회사 변경은 허용하지 않는다. 개별 효과 적용과 그 영수증은 하나의 트랜잭션으로 커밋한다. 회사별로 효과 순서대로 적용하고 실패 시 해당 회사의 후속 적용을 중단한다. 재시도는 완료 영수증을 재사용하며, 자동 정산의 기존 실패 회사 차단 절차를 유지한다.

뉴스는 부모 이벤트당 한 건이며 효과별 대상·실제 결과·대기 상태를 구분한다. 같은 회사의 서로 다른 효과 사이에 지원금 결과나 완료 상태가 섞이지 않도록 그룹별로 갱신한다. 경영 이력과 투자자 화면은 부모 제목을 표시한다. 기존 이벤트/영수증/뉴스는 재작성하지 않는다.

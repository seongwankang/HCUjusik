# 중단된 이메일 인증 이어하기

Firebase Auth 계정 생성과 이메일 인증, Firestore 참가자 등록은 별도 단계입니다. 인증 화면을 닫거나 메일 발송이 실패해도 Auth 계정이 이미 만들어졌을 수 있습니다. 계정을 삭제해 재가입시킬 필요가 없습니다.

- 같은 탭에서 새로고침하면 Auth 세션을 복원하고 인증 이어하기를 표시합니다. 새로고침만으로 메일을 추가 발송하지 않습니다.
- 탭·브라우저를 닫아 세션이 없어졌다면 기존 이메일과 비밀번호로 로그인합니다. 인증 전이면 재발송/확인 화면에서 이어갑니다. 회원가입을 다시 눌러 이미 존재하는 계정인 경우에도 비밀번호 인증 후 이어갑니다.
- 새 계정의 학생 이름은 Auth `displayName`에 저장합니다. 인증 후 학교 이메일 확인과 기존 Firestore 규칙을 거쳐 참가자와 초기 자산을 한 번만 등록합니다. 이름이 없는 이전 계정은 인증 화면에서 입력할 수 있습니다.
- 인증 확인 시 Auth 사용자를 다시 읽고 ID 토큰도 갱신합니다. 다른 탭에서 이메일 인증을 마친 뒤 돌아와 확인할 수 있습니다.
- 연결 오류와 비활성 계정은 신규 가입으로 취급하지 않습니다. 메일 발송 실패 때도 자동 로그아웃하지 않고 재발송을 제공합니다. 다른 계정으로 로그인 버튼은 세션과 화면 입력을 정리합니다.
- 비밀번호는 저장하지 않으며 기존 탭 단위 세션 유지 정책을 유지합니다. 인증 전 데이터 접근 제한과 관리자 예외는 그대로입니다.

검증: 가입 직후 중단·새로고침, 이름 복원, 인증 후 참가자 등록, 이전 계정 이름 입력, 중복 가입 시도, 메일 발송 실패·재발송, 세션 만료·계정 전환, 네트워크 오류·비활성 계정, 중복 참가 등록 시 자산 유지 테스트를 실행합니다. 실제 메일 수신과 스팸 분류는 메일함에서 별도 확인해야 합니다.

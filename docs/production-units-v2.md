# 수량 기반 생산 경제 v2

실제 보유·가동 수량으로 (판매가격 − 생산원가) × 생산량을 계산한다. 이전의 factoryRevenue/equipmentRevenue/staffRevenue 및 researchBoostBps는 새로운 모델의 계산에 사용하지 않는다.

| 투자 | 기존 가격 유지 | 효과 |
| --- | ---: | --- |
| 공장 | 2,000,000원 | 직원 정원 +25명, 자체 생산 없음 |
| 직원 | 100,000원 | 1명당 생산량 +120개/일 |
| 생산 설비 | 1,000,000원 | 생산원가 ×0.95, 반복 곱 적용 |
| R&D | 500,000원 | 판매가격 +10원 |

기본 정원10명, 기본 판매가격1,000원, 기본 원가600원. 원가는 ceil(600 ×0.95^가동설비수), 안전 최저1원. R&D는 6개 제한을 없애고 모든 자산에 동일한 저장 안전 한도1,000개를 적용한다. 이벤트 할인은 기존 가격 설정에 그대로 적용한다.

2천만 원 이하 모든 투자 조합/채용 인원을 열거하면 기본 수익은 실제 투자금의 50% 이하이며 최대 5,676,000원이다(공장4, 직원110, 생산설비1). 매출 이벤트는 이 기본 밸런스 제한 밖에서 작동한다. 공장 효율 이벤트는 가동 정원, 설비 효율 이벤트는 원가 절감에 쓰이는 유효 설비수, R&D 효율 이벤트는 정액 기술 효과에 적용한다.

## 활성화와 기존 투자 전환

productionModel=units-v2, pendingUnits에 자산별 가동 대기 수량을 기록한다. 총 수량에서 대기 수량을 빼면 현재 가동 수량이다. 07:55 이전 투자는 당일 정산, 이후 투자는 다음 정산부터 반영하며, 정산 시작 시 도래한 대기 수량만 비운다. 공장 정원을 먼저 확보하고 같은 정산에 직원을 배치할 수 있다.

production-units-migrate는 기존 수량·실제 현금·최초 판매대금·배당률·사장·완료 정산을 보존한다. 불변 투자 영수증의 activeFromDay와 실제 파괴/이탈 기록으로 대기 수량을 재구성한다. 기존 수익/효율 캐시는 0으로 비우며 과거 영수증은 남긴다. 전환 마커가 있으면 반복 변경하지 않는다. 새로운 배당 예상표를 다시 게시한다. 휴장 상태는 유지한다.

## 당일 취소

한국 날짜가 구매일과 같은 투자만 회사경영 > 오늘 투자 내역에서 취소한다. 원래 영수증의 결제액(할인 포함)을 전액 환급한다. 현재 가격을 다시 적용하지 않는다. 원본 영수증은 수정하지 않고 같은 ID의 불변 refunds 영수증을 생성하며 현금/수량/대기수량 감소를 하나의 트랜잭션으로 처리한다. 동시 재시도도 한 번만 환급한다.

정산/이벤트 처리 중에는 취소하지 않는다. 이미 파괴·이탈된 자산을 환불하는 것을 막기 위해 해당 자산 유형의 마지막 손실 이전 구매는 취소할 수 없다. 공장 취소로 정원이 줄면 초과 직원은 유휴 상태가 된다. 이미 끝난 정산 지급은 소급 취소하지 않는다. 경영이력에는 원래 투자를 취소·환불 완료로 표시한다.

## 적용 순서

1. 테스트한 firestore.rules를 Firebase hcujusik (default)에 게시한다.
2. 이 변경을 main에 반영한다. ops/production-units-v2.json 변경으로 기존 키 없는 인증의 GitHub 작업이 전환을 실행하고 Pages를 배포한다.
3. 작업 로그의 model=units-v2와 companies=verified, Pages 완료를 확인한다.

Firebase 로그인/권한이 없는 환경에서는 규칙 배포를 자동으로 수행할 수 없다. 규칙 게시 전 main 전환을 실행하지 않는다.

검증: 기본 경제의 예산 전체 탐색, 기존 수익값 무시, 6개 초과 R&D, 대기 활성화, 이벤트 파괴/지급, 사장 권한, 원가 할인 환불, 날짜/중복/동시 환불, 잠긴 정산, 현금 위조, 멱등 전환, 실제 정산.

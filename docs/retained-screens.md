# 화면과 현재 데이터 재사용

과거 기록 캐시와 별도로, 같은 로그인 세션에서 화면과 문서를 공유한다.

## 이전과 이후

이전에는 종목 → 내 자산 → 종목으로 돌아올 때 종목 화면을 새로 만들고 API를 다시 실행했다. 이제 실제 DOM 노드를 보관했다가 다시 붙인다. 변경 알림이 없으면 API 호출도 하지 않는다. 주문 입력 가격/수량, 차트·호가 탭, 차트 기간, 목록 내부 스크롤이 유지된다. 자산·순위·뉴스 상세·경영 화면도 같은 방식을 사용한다. 최대 8개 화면을 보관하고 오래된 화면은 해제한다.

`client/live-reader.js` / `live-reads.js`는 동일 문서나 동일 쿼리의 Firebase `onSnapshot` 구독을 공유한다. 여러 API가 회원·기업·계좌·호가·기업 운영 정보를 사용하더라도 각각 `getDoc`으로 다시 요청하지 않는다. 현재가 구독과 거래창의 주문장 조회도 같은 문서를 공유한다. 이미 받은 현재 값은 메모리에서 반환하고, 수정·추가·삭제가 도착하면 해당 화면을 갱신한다. 메타데이터만 같은 알림은 화면 변경으로 취급하지 않는다.

화면을 갱신할 때 기존 내용을 로딩 문구로 덮지 않는다. 종목은 주문 폼과 탭을 유지하면서 시세·계좌·기업 현황을 갱신한다. 현재 페이지의 문서 변경과 관련 없는 보관 화면은 무효화하지 않는다. 중복 변경 알림은 180ms 동안 합쳐 처리한다. 순위표의 종목 거래 집계도 장부 버전과 날짜가 같으면 재조회하지 않는다.

## 데이터 정확성과 경계

- 표시용 현재 문서는 메모리에만 보관한다. 새로고침이나 새 기기에서는 최초 구독이 필요하다. 과거 확정 기록의 IndexedDB 보관은 기존대로 유지한다.
- 변경되지 않은 구독은 화면 재방문 때 다시 만들지 않는다. Firebase 연결이 끊겼다가 재연결될 때 SDK 정책에 따른 재조회·과금이 발생할 수 있다. 구독이 받는 실제 변경도 읽기 사용량에 포함된다.
- 일반 공유 데이터 소스는 최대 100개를 보관한다. 현재가 표시 등에 사용 중인 구독과 최초 응답 대기 중인 구독은 보관 대상에서 우선 유지한다.
- 거래·관리자 변경·설비 투자 등 POST는 캐시된 회원 권한을 사용하지 않는다. 원래 서버 읽기 및 Firestore 트랜잭션/보안 규칙으로 검증한다. 변경 뒤 관련 계좌·주문장·기업 운영 등의 표시 자료를 확인한다.
- 회원 비활성화·권한 변경도 실시간 반영한다. 계정 전환·로그아웃 때 구독, 표시 데이터, 보관 화면을 비우고 늦은 이전 응답을 무시한다. 실제 결제나 실제 사용자 계좌를 테스트하지 않는다.
- 수동 새로고침 버튼은 공유 표시 자료를 다시 확인한다. 페이지 왕복 시 이 수동 새로고침은 실행하지 않는다.
- 수정 가능한 뉴스와 댓글은 영구 고정하지 않는다. 뉴스 본문 변경은 구독으로, 댓글 변경은 기존 새로 조회 버튼/작성·투표 응답으로 반영한다.

## 검증

순수 테스트는 동시 화면 2개와 반복 조회 20회가 구독 1개를 공유하는지, 동일 데이터 알림 무시, 변경값 반영, 권한 오류 시 기존 값 폐기, 로그아웃 뒤 늦은 응답 무시, 선택적 갱신, 보관 수 제한을 확인한다. 화면 테스트는 DOM 동일성·입력값·스크롤 유지와 변경된 화면만 갱신하는지 확인한다.

Firestore 에뮬레이터에서는 공유 리더를 실제 API에 연결하여 다른 계정의 거래·기업 소개 수정·내 계좌 변경이 반영되는지 확인한다. 비활성화 직후 POST가 거절되는지도 검증한다. 브라우저에서는 테스트 API로 종목 → 자산 → 종목 왕복 시 거래/경영 요약 요청 횟수가 각각 1회로 유지되고, 가격·수량·호가 탭도 유지되는지 확인한다.

이 검증은 요청 재사용과 동작 정확성을 확인한다. 실제 태블릿의 첫 접속 속도 개선률을 측정한 결과는 아니다.

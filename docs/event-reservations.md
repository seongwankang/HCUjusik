# 랜덤 이벤트 예약

관리자는 지금 발행 또는 예약 발행을 선택한다. 날짜 입력은 기기 시간대와 무관하게 한국 시간(+09:00)으로 변환한다. 예약은 현재 이후 1년 이내다. 제목·상황·복수 효과·효과별 회사·뉴스를 eventReservations/{id}에만 저장한다. 일반 참가자는 예약 문서와 목록을 읽을 수 없다. 예약 저장 시 events, news, eventQueue 또는 회사 계좌에 쓰지 않는다.

관리자 목록에서 예약 내용과 상태를 확인하거나 pending 예약을 취소할 수 있다. 실행자는 먼저 트랜잭션으로 processing 상태를 기록한다. 취소와 실행의 경합은 트랜잭션/규칙으로 제어하며 실행 시작 후에는 취소할 수 없다. 브라우저에서 예약 ID로 조기 발행할 수 없다.

신뢰된 작업이 scheduledAt <= now인 예약만 처리한다. 예약 ID를 실제 이벤트 ID로 재사용하고 기존의 회사·효과별 적용 영수증 및 이벤트별 뉴스 ID를 사용하므로 재시도 시 자금/직원/설비/뉴스가 중복 반영되지 않는다. 실패한 processing 예약은 다음 실행에서 재시도한다. 완료 후 예약과 이벤트 큐를 함께 제거한다. 로그인한 관리자의 브라우저도 같은 처리 함수를 사용한다. 서버 시각상 예약 시각이 지난 경우에만 status를 processing으로 변경할 수 있으며, payload·예약 시각·생성 시각은 바꿀 수 없다. 이벤트가 생성되고 큐를 지우는 완료 트랜잭션에서만 processing 예약을 삭제한다.

GitHub Actions에 5분 간격 events-only 실행을 요청한다. 실제 예약 실행 기록에서 수십 분 이상 지연된 사례가 확인되어, 로그인한 관리자가 사이트를 보고 있으면 별도로 30초마다 지난 예약을 처리한다. 로그인 직후와 창으로 돌아왔을 때도 즉시 확인한다. 학생 계정은 예약을 읽거나 처리하지 않는다. 관리자 이벤트 화면의 ‘지난 예약 실행 / 재시도’ 버튼도 같은 함수로 동작한다. 자동 확인에 처리할 예약이 없을 때는 화면 전체를 다시 읽지 않는다. 이 모드는 정산/스파이 발각/순위 갱신을 실행하지 않는다. 기존 07:55 정산과 15분 갱신도 유지한다. GitHub 큐·실행 지연이 가능하므로 정확한 초 단위 실행을 보장하지 않으며 예약 시각 이후 실행된다. 관리자의 브라우저가 닫혀 있으면 GitHub 실행에 의존하므로 정확한 예약 시각을 보장하지 못한다. 회사 주주명부 집계가 실패해도 예약 실행을 막지 않도록 예약 처리를 먼저 실행한다.

배포는 firestore.rules 게시 후 main 반영 순서다. 운영 데이터에 테스트 예약은 만들지 않았다. 전체 시장 초기화 목록에도 예약을 포함시켜 오래된 예약이 초기화 후 실행되지 않도록 한다.

회귀 검증: 미래 예약 조기 실행·학생 실행·예약 내용 변경 차단, 관리자 브라우저의 지연 예약 실행, 잠긴 회사 재시도, 서버와 관리자 동시 처리 시 효과·뉴스 1회만 반영, 빈 확인의 화면 재조회 생략을 확인한다. 운영 데이터에 테스트 예약을 만들지 않는다.

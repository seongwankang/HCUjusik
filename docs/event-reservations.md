# 랜덤 이벤트 예약

관리자는 지금 발행 또는 예약 발행을 선택한다. 날짜 입력은 기기 시간대와 무관하게 한국 시간(+09:00)으로 변환한다. 예약은 현재 이후 1년 이내다. 제목·상황·복수 효과·효과별 회사·뉴스를 eventReservations/{id}에만 저장한다. 일반 참가자는 예약 문서와 목록을 읽을 수 없다. 예약 저장 시 events, news, eventQueue 또는 회사 계좌에 쓰지 않는다.

관리자 목록에서 예약 내용과 상태를 확인하거나 pending 예약을 취소할 수 있다. 실행자는 먼저 트랜잭션으로 processing 상태를 기록한다. 취소와 실행의 경합은 트랜잭션/규칙으로 제어하며 실행 시작 후에는 취소할 수 없다. 브라우저에서 예약 ID로 조기 발행할 수 없다.

신뢰된 작업이 scheduledAt <= now인 예약만 처리한다. 예약 ID를 실제 이벤트 ID로 재사용하고 기존의 회사·효과별 적용 영수증 및 이벤트별 뉴스 ID를 사용하므로 재시도 시 자금/직원/설비/뉴스가 중복 반영되지 않는다. 실패한 processing 예약은 다음 실행에서 재시도한다. 완료 후 예약과 이벤트 큐를 함께 제거한다. 예약 상태를 수정하는 브라우저 API는 없다.

GitHub Actions가 5분 간격으로 events-only 모드를 실행한다. 이 모드는 정산/스파이 발각/순위 갱신을 실행하지 않는다. 기존 07:55 정산과 15분 갱신도 유지한다. GitHub 큐·실행 지연이 가능하므로 정확한 초 단위 실행을 보장하지 않으며 예약 시각 이후 실행된다. 관리자의 브라우저가 닫혀 있어도 동작한다.

배포는 firestore.rules 게시 후 main 반영 순서다. 운영 데이터에 테스트 예약은 만들지 않았다. 전체 시장 초기화 목록에도 예약을 포함시켜 오래된 예약이 초기화 후 실행되지 않도록 한다.

# 참가자 초기자금 100만 원

신규 가입과 미개설 거래계좌의 기본 현금은 client/initial-capital.js의 1,000,000원이다. Firestore 규칙도 포트폴리오·거래계좌 생성 시 같은 금액만 허용한다. 기존 계좌를 기본값으로 덮어쓰지 않는다.

## 2026-10-22 초과 지급 회수

당일 한국 시간08:00 이후 가입 완료한 student/president 중 portfolios.initialCapital=2,000,000인 계정만 대상으로 한다. 가입 시각은 사용자가 입력한 값이 아니라 Firestore users 문서의 서버 생성 시각을 사용한다. 기존 사용자·관리자·원래 100만 원으로 시작한 계정은 제외한다.

capitalAdjustments/signup-overgrant-2026-10-22/users/{uid}에 불변 회수 영수증과 변경 전 데이터를 남긴다. 같은 트랜잭션에서 기존 현금에서 100만 원을 차감하고 initialCapital을 100만 원으로 바로잡는다. 원래 현금을 100만 원으로 재설정하지 않으며, 주식·체결·매도 주문을 보존한다. 재실행해도 이미 처리한 계정은 다시 차감하지 않는다.

처음에는 100만 원 미만의 잔액을 제외했다. 사용자의 후속 지시에 따라 allowOverdraft=true이면 부족 계좌도 동일하게 차감해 음수 현금을 허용한다. 미체결 매수 예약금을 침범하는 계좌는 자동으로 주식을 처분하거나 예약금을 없애지 않고 별도 처리 대상으로 남긴다.

음수 현금은 자산/순위에서 그대로 반영한다. 새 매수는 가용 현금 범위를 넘을 수 없고, 보유 주식의 매도·취소·배당 수령은 가능하다. 공개 작업 로그에는 처리 건수만 남기며, 개별 제외 명단은 로컬에만 있는 비밀키로 해독할 수 있도록 암호화한다. 실제 사용자 정보와 비밀키를 저장소에 커밋하지 않는다.

적용 순서: firestore.rules 게시 → 코드/Pages 배포 및 회수 작업 실행 → 집계/배포 결과 검증. 과거 initial-capital-2000000 모드는 역사적 지급 작업으로만 보존되며 완료된 초기화 이후 자동 재지급하지 않는다.

# 개인 보유 현황과 종목 순위

개인 자산 순위의 이름을 누르면 같은 집계 시점의 현금과 보유 종목·수량만 표시합니다. 현금에는 미체결 매수 예약금, 주식에는 매도 대기 주식이 포함됩니다. 거래내역·주문·로그인 이메일·역할·Firebase UID를 공개하지 않습니다.

기존 계좌 `sparkAccounts/{uid}`는 학생 본인과 기존 관리자만 읽을 수 있습니다. 관리자/기존 신뢰된 정산 작업이 순위를 갱신할 때 상위 100명에 대해 승인된 필드만 `investorSnapshots/{opaqueKey}`로 투영합니다. 키는 UID에 공개용 접두사를 붙여 SHA-256으로 만든 값이며 원본 UID를 저장하지 않습니다. 참가자는 현재 순위 세대와 일치하는 문서만 단건 조회할 수 있고 목록 조회·쓰기·비로그인 접근은 차단합니다. 새 순위에 빠진 과거 문서는 세대가 바뀌어 읽을 수 없습니다. 순위와 상세 문서를 같은 배치에 기록해 서로 다른 시점의 현황이 섞이지 않게 합니다. 상세 문서를 분리해 100명의 모든 보유 주식이 순위 문서의 크기 제한을 넘기지 않게 합니다.

종목 순위는 주가·거래량·상승률·하락률 탭으로 전환합니다. 주가는 최근 체결가(첫 거래 전 초기 판매가), 거래량은 한국 시간 오늘 00:00 이후의 공개 체결 수량 합입니다. 같은 체결의 매수·매도 기록을 이중으로 합산하지 않으며 100건 단위로 끝까지 조회합니다. 등락률은 전일 마지막 체결가 대비이며 이전 체결이 없으면 초기 판매가를 기준으로 합니다. 상승/하락 종목만 각 순위에 표시하고 0%는 제외합니다. 조회 실패를 거래량 0으로 만들지 않고 해당 자료가 없는 순위에서 제외합니다.

개인 순위와 보유 현황은 기존 시간당 집계/정산 후 갱신 주기를 사용하며 종목 순위는 순위표 조회 시 계산합니다. 최초 도입 시 이전 순위에는 상세 링크가 없을 수 있으므로 집계가 한 번 필요합니다. GitHub의 `Daily settlement and rankings` 수동 실행에서 `rankings-only`를 고르면 정산·선택 이벤트를 실행하지 않고 순위·상세 투영만 갱신합니다. 기존 주기 실행은 `full`을 유지합니다. 새로운 비밀키·서비스 계정·권한은 추가하지 않습니다.

검증 항목: 승인 필드 투영, 이전 세대·비로그인·학생 쓰기 차단, 원본 계좌 접근 차단, 상위 100명 배치, 100건 초과 체결과 날짜 경계, 등락률·동점·결측 자료, 기존 자동 정산/이벤트의 회귀 테스트.

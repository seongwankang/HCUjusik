# 일일 상한가·하한가

- 기준: 전날 21:00 장 마감 당시의 표시 기준가. 마지막 체결가가 아니라 기존 90%/10% 완화 방식의 기준가를 그대로 계산한다. 캔들차트는 변경하지 않는다.
- 상한: 기준가의 2배(+100%). 하한: 기준가의 절반(-50%). 100원 호가 단위에 맞춰 하한은 올림한다. 시스템의 주문금액 한도 10억 원은 유지한다.
- 초기화한 2026-10-22는 기준가 10,000원, 하한 5,000원, 상한 20,000원이다.
- 장 마감 후 다음 날 범위를 준비한다. 당일 범위를 덮어쓰지 않고, 한국 날짜가 바뀌면 준비된 다음 날 범위를 사용한다. 거래가 없으면 마지막 기준가를 이어 쓴다. 예약 실행이 아침에 늦어져도 당일 체결을 전날 기준가에 섞지 않는다.
- 새 범위 밖의 이전 미체결 주문은 취소하고 남은 예약 현금·주식을 정확히 돌려준다. 범위 안의 주문은 유지한다. 초기 판매가가 당일 범위 밖이면 초기 물량을 그 가격에 체결하지 않는다.

## 적용 구조

`sparkBooks/{cid}.priceLimits`와 `nextPriceLimits`를 기존 IAM 정산 작업이 갱신한다. 학생·사장·사이트 관리자는 기존 문서의 이 필드를 수정할 수 없다. 신규 종목의 최초 주문장 생성 시에만 초기 가격으로 정확히 계산한 범위를 허용한다. `marketQuoteState/{cid}`는 비공개 서버 누적값이며 기본 거부 규칙을 따른다.

`daily-economy.yml`의 기존 15분 예약과 07:55 예약에서 범위를 확인한다. 하루 한 번 처리한 범위는 다시 계산하지 않는다. 가격 제한을 확인하지 못하거나 날짜가 오래된 경우 신규 주문·체결을 막고 취소는 허용한다.

`price-limits-initialize` 실행은 기업별 범위만 준비하며 개인 현금·보유 주식이나 회사 경영 자금을 초기화하지 않는다. `ops/price-limits-2026-10-22.json` 변경은 이 초기 준비만 실행한다. 과거 시장 초기화 작업을 자동 재실행하지 않는다.

## Firebase 규칙 게시

사이트 입력 검사만으로는 우회를 막을 수 없으므로 저장소의 `firestore.rules`도 게시해야 한다. 기존 계좌 원자성·소유권·학교 인증·장 운영 시간 검사를 유지하면서 주문 가격과 체결 양쪽 주문의 범위를 검사한다. 취소는 장 마감 또는 범위 변경 후에도 허용한다.

Firebase 콘솔의 `hcujusik → Firestore Database → 규칙`에서 파일 전체를 붙여넣고 **게시**한다. Firebase CLI에 로그인한 환경에서는 다음 명령으로 규칙만 게시할 수 있다.

```powershell
npx -y firebase-tools@latest deploy --only firestore:rules --project hcujusik
```

GitHub의 정산 계정은 기존 `roles/datastore.user`만 사용하며 IAM 권한을 추가하지 않는다. 규칙 게시 권한이나 CLI 로그인이 없는 경우 기존 공개 사이트와 데이터 준비 완료 여부와 별개로 규칙 게시가 남아 있음을 명시한다.

> 새 이벤트의 지속 단위는 시간이 아니라 정산 횟수입니다. [정산 횟수형 효과](company-events.md)를 참고하세요. 이미 발행된 시간형 효과만 기존 시간 기준을 유지합니다.

# 경영 이벤트 효과

관리자 → 기업 이벤트에서 랜덤 이벤트 또는 선택형 이벤트를 발행합니다. 선택형은 기존처럼 마감 전 결과를 숨기고, 마감 후 선택한 결과만 반영합니다. 이벤트를 뉴스로 자동 등록하지 않습니다.

## 추가 효과

| 효과 | 입력 | 적용 방식 |
|---|---|---|
| 회사 지원금·손실금 | ±1억 원 이내 정수, 0 제외 | 실제 주식 판매금까지 포함한 회사 자금에 한 번 지급/차감. 손실은 가용 자금까지만 차감하며 차입금을 만들지 않음 |
| 건설·채용 비용 변화 | 공장/생산 설비/R&D/직원/전체 투자, -90~+300%, 1~2160시간 | 신규 구매 가격만 변경. 원 단위 올림, 최소 1원. 기존 구매 수익은 유지 |
| 직원 충원·이탈 | ±1000명 이내 정수, 0 제외 | 충원은 현재 정원 이내에서 무료로 즉시 가동. 이탈은 재직 인원까지이며 가동·대기 직원 수익을 각각 같은 비율로 차감 |
| 설비 무상 지급 | 공장/생산 설비/R&D, 1~1000개 | 현재 정책의 수익으로 즉시 가동. 회사 현금 차감 없음. 공장·설비 각 1000개, R&D 6개·총 보너스 30% 제한 |
| 배당률 상한 | 0~100%, 1~2160시간 | 실제 정산 배당률 = min(사장 설정률, 이벤트 상한). 설정률을 덮어쓰지 않으며 기간 종료 시 원래 설정 적용 |

가동 중단·지연, 수리, 조건부 보상, 미래 비용/보상은 추가하지 않습니다. 기존 일매출·설비 효율·설비 파괴·변화 없음은 계속 지원합니다.

## 중첩·만료와 금액

동일한 투자 대상의 비용 효과와 배당 상한은 **마지막에 적용된 효과 하나**를 사용합니다. 전체 투자 비용 이벤트는 네 투자 대상의 슬롯을 모두 교체합니다. 그 후 특정 대상 이벤트를 적용하면 그 대상만 바뀝니다. 만료된 슬롯은 원래 카탈로그 가격/배당 설정으로 돌아가며 이전에 대체된 이벤트가 재활성화되지는 않습니다. 일매출·효율 이벤트는 기존의 기준 수익 대비 가산 방식을 유지합니다.

기간은 랜덤 이벤트 발행 시점 또는 선택형 마감 시점부터 계산합니다. 적용이 지연돼도 기간을 새로 늘리지 않습니다. 일회성 자금·인원·설비 변경은 자동으로 되돌아가지 않습니다. 지급·차감은 효과 영수증과 회사 변경을 한 트랜잭션으로 저장하며, 재시도나 동시 실행으로 중복 반영되지 않습니다. `result.amount` 또는 `result.count`에 실제 반영량을 남기고 관리자/회사 적용 이력에 표시합니다.

설비·직원 지급은 별도 매출로 계상하지 않습니다. 회사 지원금은 현금만 바꾸고 일매출·배당 재원에 다시 더하지 않습니다. 지급된 설비·직원의 이후 영업수익은 평소 방식으로 정산합니다. 직원 수용 한도와 기존 확정 배당·현금·다른 주주의 주식은 변경하지 않습니다.

## 신뢰 경계와 자동 처리

새 효과의 회사 자금·인원·설비·비용 조건·배당 조건 변경은 기존 관리자 또는 기존 GitHub 자동 처리 계정만 수행합니다. 학생/사장은 선택을 저장할 수 있지만 자금 지급 영수증이나 할인 조건을 직접 쓸 수 없습니다. 마감 결과 확인 시 처리가 남아 있으면 대기 상태를 표시하고, 기존 15분 간격 마감 처리 작업 또는 관리자 ‘마감 결과 적용 / 재시도’로 완료합니다. 정산 시작 전에도 마감 결과를 적용합니다. 정산 중인 기업의 효과는 실패 목록에 남겨 정산 종료 후 안전하게 재시도합니다. 랜덤 이벤트는 발행 시 즉시 대상 기업에 적용하고 실패 기업만 재시도합니다.

`companyOperations.costEvents`는 최대 네 대상의 `{eventId,percent,startsAt,endsAt}`를 보관합니다. `dividendLimit`도 같은 형태입니다. 날짜는 밀리초 정수입니다. 사장 구매 트랜잭션은 이 조건을 읽고 Firestore 규칙도 같은 가격을 검증합니다. 사장의 설정 배당률은 보존하고, 정산 기록에는 실제 사용한 `rateBps`를 고정합니다. 투자자 예상 배당도 내일 오전 9시의 상한을 사용합니다.

## 검증

기본 순수 계산 테스트와 Firestore 에뮬레이터에서 각 신규 효과, 예산·정원·보유 상한, 만료 경계, 중복 실행, 마감 전 비공개, 사장의 위조 영수증/할인/현금 쓰기 차단, 자동 처리용 Admin SDK 어댑터, 기존 거래·이벤트·배당 회귀 테스트를 확인합니다. 운영 기업에 시험 이벤트를 발행하지 않습니다.

## 투자자 공개 경영 이력

종목 화면의 ‘기업 현황·배당’에 최근 경영 이력을 시간순으로 표시합니다. 적용 영수증에서 이벤트 제목·실제 반영 결과·반영 시각·기간 상태를 읽고, 회사의 구매 기록을 같은 목록에 합칩니다. 최초 다섯 건을 바로 보여주고 이전 내역은 펼쳐볼 수 있으며 최대 최근 20건입니다. 미공개 선택지, 선택 번호, 사용자 UID/이메일은 이 공개 데이터에 포함하지 않습니다.

공장·생산 설비·R&D 건설과 직원 채용은 `companyOperations/{cid}/investments/{id}`에 자산 종류·수량·실제 지출액·구매 시각·수익 반영 날짜를 기록합니다. 할인 이벤트가 있으면 할인 후 실제 지출액을 기록합니다. 구매와 기록은 하나의 트랜잭션이며 `lastInvestment`와 Firestore 규칙의 양방향 검증으로 실제 구매 없는 이력 생성이나 기록 누락을 막습니다. 기록은 수정·삭제할 수 없습니다. 활성 참가자는 기업 투자 기록을 조회할 수 있으나, 다른 학생의 개인 계좌는 계속 조회할 수 없습니다.

과거 구매의 개별 시각·실제 구매금액은 보유 수량으로 추정해 만들어내지 않습니다. 기존 설비 현황은 유지하고 상세 투자 기록은 기능 적용 이후부터 누적합니다. 이벤트는 이미 보관된 적용 영수증이 있으면 과거 결과도 표시합니다.

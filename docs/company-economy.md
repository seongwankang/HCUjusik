# 회사경영과 뉴스 운영

## 운영 순서

1. 관리자가 기업을 등록한다. 주식 기준가격과 발행주식은 각각 1~1,000,000의 정수다.
2. 참가자 관리에서 회원의 역할을 사장으로 바꾸고 담당 기업을 지정한다.
3. `기업 경영`에서 기업을 고르면 담당 사장·관리자의 최초 조회 시 회사 계좌가 자동 생성된다. 기존 계좌는 그대로 사용한다. 별도 준비 버튼은 없다.
4. 기본 경영 정책으로 바로 투자할 수 있다. 관리자는 `회계·배당` 탭의 `설비·채용 가격 및 수익 정책`에서 이후 구매의 가격·수익을 변경할 수 있다.
5. 최초 발행 주식이 팔리면 판매대금이 회사의 투자 가능 자금에 반영된다. 학생끼리 거래한 돈은 회사 수입이 아니다.
6. 사장 또는 관리자가 공장·생산 설비·연구 시설을 구매한다. 회사 돈만 사용하며 개인 현금과 구분된다.
7. 관리자가 기업별 배당률(0~100%, 0.01% 단위)을 설정한다. 기본값은 0%다.
8. `회계·배당` 탭에서 한국 시간 날짜별로 `오늘 수익·배당 정산`을 한 번 실행한다. 정산은 관리자만 할 수 있다.

## 화면 구성

상단에서 보유 공장·생산 설비·R&D센터·직원 수를 확인한다. `지금 고용 가능`은 정원 여유와 현재 자금으로 감당 가능한 채용비를 함께 반영한 수치이며, 정산·미처리 이벤트·분류 작업으로 투자가 잠겼으면 0명으로 표시한다. `정원 여유`는 자금과 별개인 빈자리다.

`시설·채용`에서 투자, `이벤트`에서 선택과 결과 확인, `회계·배당`에서 정산·정책 설정을 한다. 선택 대기 이벤트는 탭에 건수가 표시된다. 세부 계산 기준과 투자 비교는 접힌 안내에서 확인한다. 모바일에서는 시설·인력 현황을 먼저 표시한다.

## 매출과 배당 기준

- 구매한 설비는 **구매 다음 한국 날짜**부터 매출에 포함된다. 구매 시점의 일매출을 고정하며 공통 정책 변경은 새 구매에만 적용한다.
- 매출은 가격 변동이나 실제 외부 매출이 아닌, 관리자가 설정한 교육용 가상 매출이다.
- 정산 시점의 발행 후 판매 수량과 실제 보유 주식을 사용한다. 매도 주문에 예약된 주식도 보유 주식이다. 미판매 주식에는 배당하지 않는다.
- `배당 예산 = floor(일매출 × 배당률 / 10000)` (배당률 내부 단위: basis points).
- `1주당 배당 = floor(배당 예산 / 판매된 주식 수)`.
- `학생 지급액 = 1주당 배당 × 해당 학생 보유 수량`.
- 회사는 `일매출 - 실제 배당 총액`을 보유한다. 원 단위 나머지도 회사 자금에 남는다. 주주가 없으면 전액 회사가 보유한다.
- 예: 일매출 7,000원, 배당률 50%, 판매된 주식 40주 → 주당 87원, 총 배당 3,480원, 회사 유보 3,520원.
- 비활성화된 회원도 기존 보유 주식이 있다면 해당 수량은 정산 대상에 포함한다. 비활성 계정은 거래할 수 없다.

## 무료 Spark 실행 구조와 복구

Firebase Auth + Firestore + GitHub Pages를 유지한다. 별도 서버/Cloud Functions/유료 스케줄러를 추가하지 않는다. **백그라운드 자동 정산은 없다.** 관리자가 접속해서 실행한 한국 날짜를 정산하며, 누락된 날짜의 소급 정산은 하지 않는다.

정산 시작 트랜잭션이 기업 자금·매출·배당률·판매 주식 수를 고정하고 해당 종목 거래와 설비 투자를 잠근다. 관리자가 주주 계좌를 100개씩 조회해 각 지급을 개별 트랜잭션으로 처리한다. 학생 현금 증가, 기업별 영수증, 학생 배당 내역, 지급 누계를 한 번에 기록한다. 같은 주주 영수증은 다시 생성할 수 없어 재실행해도 이중 지급하지 않는다.

창 닫기/통신 실패 시 `정산 이어하기`를 누른다. 이미 지급한 계좌는 건너뛴다. 총 지급 주식 수가 판매된 주식 수와 일치하고 실제 지급액이 정산 배당 총액과 일치해야 정상 종료하고 거래 잠금을 해제한다. 오류가 나면 DB의 정산 문서를 지우거나 잠금만 강제로 해제하지 말고 원인을 확인한 뒤 이어서 처리한다.

주주 N명당 지급 단계는 대략 4N회 문서 쓰기와 정산 시작/종료 3회 쓰기를 사용한다. 그 밖의 조회와 거래도 무료 사용량을 소모하므로 운영 규모에 맞춰 Firebase 사용량을 확인한다. 진행 화면의 완료 메시지를 확인한다.

## 데이터와 권한

- `sparkBooks/{companyId}.issuerCash`: 최초 판매 누적 수입. 줄이거나 다시 받지 않는다.
- `companyOperations/{companyId}`: 실제 회사 자금, 이미 반영한 최초 판매 수입, 설비 수, 가동/대기 매출, 배당률, 정산 잠금·누계.
- `economyConfig/main`: 관리자가 정하는 새 설비 비용·매출.
- `companyOperations/{companyId}/days/{day}`: 변경 불가 일일 매출·배당 스냅샷.
- `.../days/{day}/payouts/{uid}`: 변경 불가 중복 지급 방지 영수증. 관리자와 본인만 조회한다.
- `sparkAccounts/{uid}/dividends/{companyId_day}`: 학생 본인에게만 보이는 배당 내역. `내 자산`에서 최근 30건을 표시한다.

관리자는 신뢰된 모의투자 운영자다. 회사 운영값·일일 정산·설비 정책을 관리하고 배당 지급을 위해 학생 계좌를 제한된 쿼리로 조회한다. 일반 학생은 현금·주식·운영값을 직접 수정할 수 없다. 사장은 본인에게 배정된 기업에서 설정된 비용으로 설비만 구매할 수 있다. 학생 간 매매의 기존 원자성·가격/시간 우선·금액 검증은 유지한다. 보안 규칙을 변경할 때 에뮬레이터 테스트를 실행하고 넓은 학생 배포 전에 검토한다.

## 뉴스 검증과 사용

관리자 → 뉴스·공지 → 제목/내용/대상 기업 → 저장. 문서 ID는 자동 생성된다. 목록을 누르면 같은 문서를 수정할 수 있다. 전체 공지 선택 시 기존 기업 이름을 지운다. 게시 시각은 Firestore 서버 시간이 적용된다.

시장 뉴스에 들어갈 때 새로 조회하며, 관리자 저장 후에도 사이드바와 뉴스 데이터가 갱신된다. 줄바꿈을 유지하고 HTML은 텍스트로 표시해 코드 실행을 방지한다. 일반 학생의 뉴스 작성·수정과 과거 게시 시각 위조는 보안 규칙이 거부한다. 운영 데이터에 테스트 뉴스를 넣지 않고 실제 API/보안 규칙과 합성 학생 계정을 연결한 로컬 에뮬레이터에서 등록·수정·학생 화면 표시를 확인했다.

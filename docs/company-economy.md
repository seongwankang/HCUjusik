# 회사경영과 뉴스 운영

## 운영 순서

1. 관리자가 기업을 등록한다. 주식 기준가격과 발행주식은 각각 1~1,000,000의 정수다.
2. 참가자 관리에서 회원의 역할을 사장으로 바꾸고 담당 기업을 지정한다.
3. `기업 경영`에서 기업을 고르면 담당 사장·관리자의 최초 조회 시 회사 계좌가 자동 생성된다. 기존 계좌는 그대로 사용한다. 별도 준비 버튼은 없다.
4. 기본 경영 정책으로 바로 투자할 수 있다. 관리자는 `회계·배당` 탭의 `설비·채용 가격 및 수익 정책`에서 이후 구매의 가격·수익을 변경할 수 있다.
5. 최초 발행 주식이 팔리면 판매대금이 회사의 투자 가능 자금에 반영된다. 학생끼리 거래한 돈은 회사 수입이 아니다.
6. 사장 또는 관리자가 공장·생산 설비·연구 시설을 구매한다. 회사 돈만 사용하며 개인 현금과 구분된다.
7. 담당 사장 또는 관리자가 기업별 배당률(0~100%, 0.01% 단위)을 설정한다. 기본값은 0%다. 변경한 비율은 다음 정산에 적용하며 정산 중에는 변경할 수 없다. 사장은 다른 기업의 비율이나 자금·매출·정산 상태를 바꿀 수 없다.
8. `회계·배당` 탭에서 한국 시간 날짜별로 `오늘 수익·배당 정산`을 한 번 실행한다. 수동 정산은 관리자만 오전 9시 이후 실행할 수 있다. 이미 시작한 정산의 복구는 시간에 관계없이 가능하다.

## 화면 구성

상단에서 보유 공장·생산 설비·R&D센터·직원 수를 확인한다. `지금 고용 가능`은 정원 여유와 현재 자금으로 감당 가능한 채용비를 함께 반영한 수치이며, 정산·미처리 이벤트·분류 작업으로 투자가 잠겼으면 0명으로 표시한다. `정원 여유`는 자금과 별개인 빈자리다.

`시설·채용`에서 투자, `이벤트`에서 선택과 결과 확인, `회계·배당`에서 정산·정책 설정을 한다. 선택 대기 이벤트는 탭에 건수가 표시된다. 세부 계산 기준과 투자 비교는 접힌 안내에서 확인한다. 모바일에서는 시설·인력 현황을 먼저 표시한다.

## 매출과 배당 기준

경영 화면은 `다음 정산 예상 영업수익` 하나와 정산 예정 시각을 표시한다. 투자자 화면의 예상 배당도 같은 정산 시점을 사용한다. 기존 대기 수익은 초기화하지 않는다. 자정부터 9시 전까지 같은 날 정산용 투자를 여러 번 합산할 수 있다. 9시 정산 작업이 지연되어 기존 대기 수익이 남아 있으면 완료 전까지 다음 회차 투자를 막아 서로 다른 회차 수익이 섞이지 않도록 한다. GitHub Actions의 실제 실행은 9시보다 늦을 수 있지만 투자 반영 회차는 9시를 기준으로 고정한다.

- 설비·직원·R&D는 **한국 시간 오전 9시 전에 투자하면 당일 9시 정산부터, 9시 정각 이후에는 다음 날 9시 정산부터** 수익에 포함된다. 구매 시점의 일매출을 고정하며 공통 정책 변경은 새 구매에만 적용한다.
- 매출은 가격 변동이나 실제 외부 매출이 아닌, 관리자가 설정한 교육용 가상 매출이다.
- 정산 시점의 발행 후 판매 수량과 실제 보유 주식을 사용한다. 매도 주문에 예약된 주식도 보유 주식이다. 미판매 주식에는 배당하지 않는다.
- `배당 예산 = floor(일매출 × 배당률 / 10000)` (배당률 내부 단위: basis points).
- `1주당 배당 = floor(배당 예산 / 판매된 주식 수)`.
- `학생 지급액 = 1주당 배당 × 해당 학생 보유 수량`.
- 회사는 `일매출 - 실제 배당 총액`을 보유한다. 원 단위 나머지도 회사 자금에 남는다. 주주가 없으면 전액 회사가 보유한다.
- 예: 일매출 7,000원, 배당률 50%, 판매된 주식 40주 → 주당 87원, 총 배당 3,480원, 회사 유보 3,520원.
- 비활성화된 회원도 기존 보유 주식이 있다면 해당 수량은 정산 대상에 포함한다. 비활성 계정은 거래할 수 없다.

## 무료 Spark 실행 구조와 복구

Firebase Auth + Firestore + GitHub Pages를 유지한다. 별도 서버/Cloud Functions/유료 스케줄러를 추가하지 않는다. 자동 정산 연결 절차와 제약은 [자동 정산·순위표](automation-and-rankings.md)를 따른다. 연결 전에는 자동 정산이 실행되지 않는다. 관리자가 접속해서 실행한 한국 날짜를 정산하며, 누락된 날짜의 소급 정산은 하지 않는다.

정산 시작 트랜잭션이 기업 자금·매출·배당률·판매 주식 수를 고정하고 해당 종목 거래와 설비 투자를 잠근다. 관리자가 주주 계좌를 100개씩 조회해 각 지급을 개별 트랜잭션으로 처리한다. 학생 현금 증가, 기업별 영수증, 학생 배당 내역, 지급 누계를 한 번에 기록한다. 같은 주주 영수증은 다시 생성할 수 없어 재실행해도 이중 지급하지 않는다.

창 닫기/통신 실패 시 `정산 이어하기`를 누른다. 이미 지급한 계좌는 건너뛴다. 총 지급 주식 수가 판매된 주식 수와 일치하고 실제 지급액이 정산 배당 총액과 일치해야 정상 종료하고 거래 잠금을 해제한다. 오류가 나면 DB의 정산 문서를 지우거나 잠금만 강제로 해제하지 말고 원인을 확인한 뒤 이어서 처리한다.

주주 N명당 지급 단계는 대략 4N회 문서 쓰기와 정산 시작/종료 3회 쓰기를 사용한다. 그 밖의 조회와 거래도 무료 사용량을 소모하므로 운영 규모에 맞춰 Firebase 사용량을 확인한다. 진행 화면의 완료 메시지를 확인한다.

## 데이터와 권한

- `sparkBooks/{companyId}.issuerCash`: 최초 판매 누적 수입. 줄이거나 다시 받지 않는다.
- `companyOperations/{companyId}`: 실제 회사 자금, 이미 반영한 최초 판매 수입, 설비 수, 가동/대기 매출, 배당률, 정산 잠금·누계.
- `economyConfig/main`: 관리자가 정하는 새 설비 비용·매출.
- `companyOperations/{companyId}/days/{day}`: 변경 불가 일일 매출·배당 스냅샷.
- `.../days/{day}/payouts/{uid}`: 변경 불가 중복 지급 방지 영수증. 관리자와 본인만 조회한다.
- `sparkAccounts/{uid}/dividends/{companyId_day}`: 학생 본인에게만 보이는 배당 내역. `내 자산`에서 최근 30건을 표시한다.

관리자는 신뢰된 모의투자 운영자다. 회사 운영값·일일 정산·설비 정책을 관리하고 배당 지급을 위해 학생 계좌를 제한된 쿼리로 조회한다. 일반 학생은 현금·주식·운영값을 직접 수정할 수 없다. 사장은 본인에게 배정된 기업에서 설정된 비용으로 설비만 구매할 수 있다. 학생 간 매매의 기존 원자성·가격/시간 우선·금액 검증은 유지한다. 보안 규칙을 변경할 때 에뮬레이터 테스트를 실행하고 넓은 학생 배포 전에 검토한다.

## 뉴스 검증과 사용

관리자 → 뉴스·공지 → 제목/내용/대상 기업 → 저장. 문서 ID는 자동 생성된다. 목록을 누르면 같은 문서를 수정할 수 있다. 전체 공지 선택 시 기존 기업 이름을 지운다. 게시 시각은 Firestore 서버 시간이 적용된다.

시장 뉴스에 들어갈 때 새로 조회하며, 관리자 저장 후에도 사이드바와 뉴스 데이터가 갱신된다. 줄바꿈을 유지하고 HTML은 텍스트로 표시해 코드 실행을 방지한다. 일반 학생의 뉴스 작성·수정과 과거 게시 시각 위조는 보안 규칙이 거부한다. 운영 데이터에 테스트 뉴스를 넣지 않고 실제 API/보안 규칙과 합성 학생 계정을 연결한 로컬 에뮬레이터에서 등록·수정·학생 화면 표시를 확인했다.

## 산업스파이

- 1명당 고용비 **1,000,000원**, 대상 영업수익의 **0.5%**, 회사당 **최대 10명**, **기간 제한 없이 계속 활동**한다. 같은 기업에 10명을 보내면 합계 5%다. 매 정산 추가 고용비가 들지 않는다.
- 담당 사장/관리자만 회사 자금으로 1명씩 고용한다. 대상은 자기 회사를 제외한, 계좌와 주식 원장이 준비된 상장 기업이다. 각 인원은 독립적으로 대상을 지정한다. 9시 전 고용은 당일, 이후 고용은 다음 정산부터 적용한다. 중도 해고·환불·대상 변경은 제공하지 않는다.
- 기존 유료 계약은 남은 횟수가 양수인 인원을 유지하여 0.5%로 무기한 활동하게 한다. 이미 만료된 계약은 부활하지 않는다. 기존 영수증·이력은 보존하며 운영 데이터 일괄 수정이나 초기화는 하지 않는다. 이전 spyPolicy 문서의 가격·비율·횟수는 새 정책을 덮어쓰지 못한다.
- companySpies/{cid}.agents는 0~9 슬롯을 사용한다. 신규 고용은 빈/종료 슬롯 하나만 바꾸며 다른 인원의 계약을 수정할 수 없다. hires/{hireId} 영수증·회사 현금 차감·명단 버전 갱신이 하나의 트랜잭션이다. 11번째 고용과 동시 고용의 초과를 차단하고, 명단 변경으로 생기는 규칙 충돌은 최신 버전을 확인해 재시도한다.
- 계산 순서: 이벤트 → 일반 영업수익·주주 배당 → **별도 산업스파이 이체**. 불변 days/d{day}.revenue를 기준으로 계산한다. 같은 회사에서 같은 대상에 보낸 인원은 비율을 합쳐 원 단위 계산한다. 훔친 돈을 다른 스파이의 기준 매출에 포함하지 않으며 당일 배당에도 포함하지 않는다.
- 동일 대상의 총 피해 한도는 일매출 10%와 이체 직전 가용 회사 자금 중 작은 금액이다. 초과 요청은 비례 배분하고 원 단위 나머지를 결정적인 순서로 배분한다. 받은 돈으로 같은 단계의 피해를 충당하지 않으며 회사 간 자금 합계를 보존한다.
- 기존 IAM 정산 작업이 관련 기업의 일반 정산 완료 후 단일 트랜잭션으로 spyRounds/d{day}, 현금, 인원별 마지막 처리 날짜 및 history/d{day}를 기록한다. 활동 인원을 줄이거나 기간을 차감하지 않는다. 동시 실행·재시도에도 중복 이체하지 않는다. 관련 기업 정산이 중단되면 전체 스파이 단계가 대기한다. 개별 수동 정산 후에도 스파이 단계는 다음 자동 작업에서 처리한다(15분 주기, GitHub 지연 가능).
- 비상장/삭제/계좌 소실 기업은 그 회차 이체에서 제외한다. 지난 날짜 소급 정산은 하지 않는다. 한 번에 관련 기업 최대 100개를 처리하며 상한·자금 오류면 부분 이체 없이 실패한다. 새 서버·비밀키·유료 서비스는 필요 없다.
- 규칙을 먼저 게시한 뒤 사이트를 배포한다. demo-industrial-spies-ten 에뮬레이터에서 10명·11명 차단·동시 고용·이전 계약 호환·정산 6회 이상 지속·중복 방지를 검증한다. 학생 UID와 이메일은 스파이 문서에 저장하지 않는다.

## 개인 거래내역·평균 매입가

- 내 자산에서 전체 개인 체결 내역을 최근순으로 30건씩 펼쳐 볼 수 있다. 주문 접수·미체결·취소·배당은 매수/매도 거래내역에 포함하지 않는다. 전량 매도한 종목의 과거 체결 내역도 유지한다.
- 평균 매입가는 종목별 이동평균 취득원가다. 추가 매수는 남은 취득원가와 새 체결금액을 합쳐 평균을 갱신한다. 일부 매도는 남은 원가만 비례 감소하므로 평균가는 유지하고, 전량 매도하면 원가를 0으로 초기화한다. 이후 재매수는 새 매입가격부터 계산한다. 미체결 주문은 평균을 바꾸지 않는다.
- 자신의 불변 sparkAccounts/{uid}/fills만 30건씩 문서 ID 커서로 끝까지 읽는다. 종목별 marketVersion 순서로 재구성하므로 최근 30건에 한정하거나 같은 시각의 체결을 임의 정렬하지 않는다. 원가는 백만분의 1원 정밀도로 계산하고 화면에는 소수점 최대 2자리로 표시한다.
- 조회 전후 계좌 version이 같을 때만 평균과 기록을 반환한다. 조회 중 체결·취소·배당 등으로 버전이 바뀌면 재조회하고 같은 버전은 메모리 캐시로 읽기 비용을 줄인다. 3회 연속 변경되면 재조회 안내를 표시한다. 체결 기록과 현재 수량이 다르면 해당 종목의 평균가는 ‘—’로 남기며 초기 기준가나 현재가로 추정하지 않는다.
- 내 자산과 종목 거래창이 같은 계산 함수를 사용한다. 다른 참가자의 개인 거래내역은 읽거나 노출하지 않는다. 기존 Rules의 본인 전용 읽기와 체결 영수증 불변 조건을 그대로 사용하며 원본 계좌·체결·보안 규칙은 변경하지 않는다.

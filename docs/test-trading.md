# 테스트 매매

> 아래는 이전 기준가격 즉시 매매 기록입니다. 현재 화면은 [지정가 주문장](limit-exchange.md)으로 대체되었습니다. 아래의 규칙 게시 절차는 새 매칭 서버 연결 절차가 아닙니다.

기존 공식 portfolios 자산은 변경하지 않습니다. 별도 tradeTests/{uid} 계좌를 처음 열 때 가상 100만 원을 한 번 지급합니다. TESTA(test-a), TESTB(test-b)만 거래하며, listed 기업의 현재 referencePrice에 즉시 체결합니다. 수수료·호가·상대방·발행량 제한·가격 변동·경영 효과는 없는 기능 시험용입니다. 공식 행사 매매 규칙이 아닙니다.

## 활성화와 사용

1. 이 변경의 전체 firestore.rules를 Firebase Console → Firestore Database → Rules에 붙여 넣고 게시합니다. 기존 규칙 일부에 allow write를 추가하지 마세요.
2. GitHub Pages 배포 후 새로고침하고 로그인합니다.
3. 주식시장 → 테스트 기업 보기 → 테스트 매매에서 구분과 수량을 입력하고 주문합니다.
4. 내 자산 아래 별도 테스트 계좌에서 현금·보유 수량·최근 체결 20건을 확인합니다.

규칙을 게시하기 전에는 테스트 계좌가 열리지 않고 주문 버튼이 비활성화됩니다. 기존 공식 주문 경로는 계속 거부합니다. 테스트 계좌는 재접속해도 유지하며 화면에서 초기화·삭제하지 않습니다.

## 저장 및 검증

계좌: cash 정수, positions 맵(test-a/test-b 수량 정수), version 정수, lastOrderId 문자열. 하위 orders/{UUID}: companyId, side, quantity, price, total, version, createdAt. 이메일·비밀번호는 저장하지 않습니다.

SDK 트랜잭션에서 계좌·기업·기존 주문을 읽고, 계좌와 변경 불가 체결 문서를 함께 기록합니다. 재전송에는 같은 주문 ID를 사용해 한 번만 체결합니다. 보유 수량/현금은 음수가 될 수 없고, 주문 당시 가격과 서버 기업가격이 다르면 거부합니다. Rules는 getAfter로 주문과 계좌 변경의 일치, 가격·현금·수량 변화, 서버 시각을 독립 검증합니다. 자기 계좌만 조회/거래할 수 있으며 비활성·미인증 학생은 거부합니다. 클라이언트 버튼 제한만 신뢰하지 않습니다.

## 검증 결과

Firestore 에뮬레이터에서 정상 매수/매도, 중복 전송·내용 변경, 동시 주문·두 세션의 초과 지출, 잔액 부족·초과 매도·이전 가격, 익명·다른 사용자·미인증·비활성 접근, 계좌 직접 증액·초기화·삭제, 체결 변조·고아 주문, 음수·소수·과대 수량, 다른 종목 수량 조작, 필드 추가/누락, 과거 시각, 공식/거래정지 종목 공격을 검사했습니다. 정상 경로는 성공하고 공격은 거부됐습니다. 전체 기본 테스트 37개, 규칙 테스트 16개 통과.

원격 규칙 게시와 실제 로그인 계정의 체결은 별도 확인해야 합니다. 트랜잭션 및 Rules를 포함한 기능 시험용 구현이며 실제 금융 거래에 사용하지 않습니다. 추후 공식 시장·총 발행량·상대 주문 매칭에는 별도 설계가 필요합니다.
